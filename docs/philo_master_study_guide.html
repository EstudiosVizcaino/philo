Runtime architecture and communication

main()
 ├─ check_args()
 ├─ init_data()
 │   ├─ init_mutexes()
 │   │   └─ init_forks()
 │   └─ init_philos()
 ├─ start_threads()
 │   ├─ create philosopher threads (philo_routine)
 │   ├─ create monitor thread (monitor_routine)
 │   └─ set start_time + ready barrier under meal_mutex
 ├─ join philosophers
 ├─ join monitor
 └─ cleanup()

Who writes what

  • Philosopher threads write: own last_meal_time, own meals_eaten, maybe global finished_eating.
  • Monitor thread writes: dead, all_ate.
  • Main thread writes setup fields before releasing ready.

Mutex roles

  • forks[i]: ownership of physical fork i.
  • meal_mutex: protects stop flags/timestamps/counters/start barrier fields.
  • print_mutex: one line at a time to stdout.

File-by-file explanation

philo.h — data model + contracts

Defines t_philo (per-thread local + shared refs) and t_data (shared config/state). Key defense sentence: “Every shared mutable field has an explicit mutex owner.”

main.c — validation, startup, shutdown
  • Rejects invalid CLI values and wrong argument counts.
  • Thread creation is fail-safe via abort_threads().
  • Important barrier design: all workers spin on ready, then start together from one start_time.
init.c — deterministic initialization
  • Computes think_time = max(0, (die - eat - sleep) / 2).
  • Builds circular fork topology: philosopher i uses fork[i] and fork[(i+1)%N].
  • Provides symmetric cleanup to avoid leaks.
routine.c — philosopher behavior loop
  • Single philosopher edge case: can take one fork only, then waits until death.
  • Deadlock prevention: odd and even philosophers acquire forks in opposite order.
  • Startup smoothing: even IDs initially sleep time_to_eat for cleaner fork alternation.
monitor.c — stop conditions watchdog
  • Polls all philosophers every 1ms.
  • Death if now - last_meal_time > time_to_die (strictly greater).
  • Completion when finished_eating == num_philos and must_eat is configured.
utils.c — low-level helpers
  • ft_usleep(): tighter timing than a single long usleep.
  • print_status(): lock order is print_mutex → meal_mutex.
  • is_dead(): unified stop check for routines.

Function atlas (what each function does and why)

Odd vs Even philosophers: what changes and why

  • Fork order asymmetry: odd IDs take left→right, even IDs take right→left.
  • Reason: breaks circular wait (deadlock precondition).
  • Initial stagger: even IDs delay by time_to_eat before first attempt.
  • Reason: avoids a synchronized initial stampede for forks with large N.
  • Odd N extra think delay: add computed think_time to keep cycle under death budget.

Intuition: with odd N, resource contention is inherently unbalanced. The extra think delay and stagger reduce starvation risk by dephasing thread behavior.

Oral defense Q&A (high-value answers)

“How do you prevent data races?”

By defining ownership: fork mutexes protect fork acquisition; meal_mutex protects all shared lifecycle/time/counter fields; print_mutex serializes logs. Reads/writes of protected data occur under the corresponding mutex.

“How do you prevent deadlock?”

Circular wait is broken with asymmetric fork acquisition (odd left-first, even right-first). This removes the possibility that all threads hold one fork while waiting forever for the other in the same direction.

“Why a monitor thread instead of checking death inside each philosopher only?”

A dedicated monitor centralizes death and completion checks, making stop semantics deterministic and easier to reason about. Philosophers focus on behavior loop; monitor handles global termination conditions.

“Why do even philosophers wait at startup?”

The startup delay (equal to time_to_eat) dephases competing groups. Without it, all threads can contend instantly and unfairly, especially at larger N with tight timing margins.

“What happens if thread creation fails halfway?”

abort_threads() marks simulation dead/ready under mutex and joins already-created philosopher threads, then startup returns failure and cleanup runs safely.
